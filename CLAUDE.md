# rawdot — Shopify storefront

Direct-to-consumer store for rawdot gaming peripherals: mouse skates, glasspads, gaming arm sleeves. Sells in Mexico only (owner, 14 Oct 2026; maybe the US later). The theme still handles other currencies and languages if markets are added.

## Project status

- **Phase: live (15 Oct 2026).** The owner asked to replace the original site; `rawdot (new theme)` (#208512188785) was published on 15 Oct 2026. The previous live theme `Rawdot/main` (#197611290993, GitHub-connected to `Alteu/Rawdot`) is kept unpublished as the rollback. Further publishing decisions stay with the owner.
- **Design is not finalized.** Specific typography, layouts and animations are confirmed with the owner before use. Don't invent a new visual style or copy other brands' designs.

## Design decisions (approved 13 Oct 2026)

- **Sell first, explain second.** A visitor's first screen shows the product, its price and add-to-cart, with no scrolling, on desktop and mobile. Story, placement guide, installation and FAQ come after, or on demand. Wallhack's buying patterns are the model (`docs/research/wallhack-analysis.md`); the model is _how it sells_, not its look.
- **Black-and-white base.** Keep the monochrome look of the current site.
- **No blue accent.** It only existed because of the Ice Version's name. Buy buttons are solid black (white on dark backgrounds). A product-specific accent may be revisited later with the owner.
- **No oversized editorial headlines** like the current site's "One shape. More freedom." Headings are compact and informational: product name, what it is, price.
- **Visual system (revised 13 Oct 2026 after owner feedback: "too black", "too AI-made"):** white/off-white pages with a black header and black footer. Wallhack-like first screen: product large on the left, name + fact row + type tag + one-line description + "See more +" link + black "Add to cart · price" bar bottom-right. Original-site details: palette (#fbfbf9, #111214, #747572, #deded9), spaced uppercase labels ("01 / placement"), fact row (big value, small label), faint dot grid and thin rings. No glassmorphism, no giant outlined words, no pill tabs, no monospace UI.
- **Typography (owner choice, 13 Oct 2026):** Jost ("classic geometric") for all theme text, from Shopify's font library (theme setting `type_body_font`, weights 400/500/600). Light tracking only (no tighter than -0.02em); Jost is already compact. Languages Jost doesn't cover (ja, ko, zh-CN, ar) fall back to system fonts.
- **Product names:** the first glasspad is called **11:37** (the name on the pad), type Speed; show it as the title with "rawdot / glasspads" above it. A second glasspad type may come later; until then glasspads have no version tabs.
- **Logo intro:** skipped for visitors arriving from an ad or campaign link (utm\_\*, fbclid, gclid, ttclid…; owner, 15 Oct 2026). On the first page view of a browser tab, the black rawdot "r" draws on white, the dot glides in, then the screen wipes up (~1.8 s). Shown in the theme editor too. Reduced motion: the finished logo fades out instead. Off via a theme setting.
- **Switching versions:** a tab row at the top of the product panel showing the **type only** ("Speed | Control"); the product name is the title. This avoids "Control Version · CONTROL" (owner chose the names before the types; renaming is optional). The black type badge is hidden when tabs are shown. Animated transition; no arrows, "1 of 2" or floating chips. Header links (Skates, Glasspads, Arm sleeves) switch categories on the homepage. On phones the add-to-cart bar is fixed to the bottom.
- **Below the first screen: a guide per product** (block setting `guide`). Content belongs to the selected version only; never show skate content for glasspads or sleeves. `skates` (`snippets/guide-skates.liquid`, used by Ice Version and Control Version with the name swapped in): recommended placements, what's included, how to install (original installation images, English or Spanish; other languages get the steps as text under the English images, an owner-approved exception to the no-text-in-images rule), FAQ. `coming_soon` (`snippets/guide-coming-soon.liquid`, glasspad and arm sleeve): known facts plus notify me. Copy rules from the owner: skate placement is about dot count, position and keeping the mouse level (more dots = more control, fewer = faster), never "grip"; universal dots fit any mouse, so answer "Yes"; treat Control Version as available in copy.
- **Product photos (14 Oct 2026, owner: "recórtalas"):** product photos float on the page with no frame (background removed, soft drop shadow), like the 11:37 glasspad; the owner agreed framed squares (white box / black box) looked pasted on and made Speed and Control clash. The stage is a swipeable gallery (scroll snap) with small round dots under it (the brand dot). Cutouts are theme files set in the block setting `image_asset` (comma-separated), which replaces the Shopify product's own photos. The owner makes the cutouts (transparent PNG/WebP; owner rejected Claude's automatic cutouts on 14 Oct 2026); Claude only trims them and adds them. Order per version: pack, then the sheet beside a mouse with dots installed. The side views of the mouse (`*-3-cutout.webp`) are kept in assets but not shown (owner, 14 Oct 2026: looks better without them). Ice Version = `ice-version-1-cutout.webp, ice-version-2-cutout.webp`; Control Version = `control-version-1-cutout.webp, control-version-2-cutout.webp`; 11:37 = `glasspad-cutout.webp`; Arm Sleeve = `arm-sleeve-1-cutout.webp, arm-sleeve-2-cutout.webp`. In-use and detail photos of the sleeve are not product photos: they are shown under the arm sleeve's coming-soon guide (block setting `lifestyle_asset`, comma-separated, two per row at their own proportions: `arm-sleeve-lifestyle.webp, arm-sleeve-lifestyle-desk.webp`, then the transparent close-ups `arm-sleeve-detail-logo-cutout.webp, arm-sleeve-detail-cuff-cutout.webp`, which float with no background; owner: they were given as PNGs without background on purpose). "What's included" uses a per-version cutout (block setting `included_asset`: `included-ice-cutout.webp`, `included-control-cutout.webp`). Recommended placements have no caption under the images (owner, 15 Oct 2026: the mouse names are already in the images). Clear the setting to fall back to Shopify's photos. Files named `*-cutout*` get the drop shadow; other photos get rounded corners and a shadow. Theme photos render through `snippets/theme-image.liquid`, which knows each file's size and its `-480`/`-960` copies (srcset); a new photo file needs those copies and an entry in its list. A 3D model in the product's media replaces the photos.
- **Reviews:** `sections/reviews.liquid`, customer screenshots as blocks (an uploaded image, or a theme file in the block setting `image_asset`, e.g. `review-1.webp`; theme files are cropped to the chat bubbles, 900 px wide plus a `-480` copy, listed in `snippets/theme-image.liquid`; the block's `alt` holds the review text); shown with one category (skates by default) and hidden until it has at least one screenshot. Nine added 15 Oct 2026 (owner's customer DMs, `review-1`…`review-9`).
- **About us:** an "About" link on the right of the header (and in the phone menu) opens a full-screen view: black brand panel with the real wordmark image (never RAWDOT typed in the UI font), one-line lead, then "How it started" as a four-step timeline (the problem, our answer, across Mexico ("gamers de todo México", owner 15 Oct 2026), next: glasspads). No social links there.
- **See more** opens a dialog with information that is not on the first screen: a "Details" table (block settings `detail_1..4`, e.g. Type, Shape, Fits, Surfaces), the notify form for coming-soon products, and for skates "In the guide" links that scroll to placement, what's included, installation and FAQ. Never repeat the fact row or tagline there. No "view full product page" link: customers buy from the homepage. Product pages still exist (Shopify needs them for search, shared links and checkout) and use the same buy box: `sections/main-product.liquid` has the same fields as a showcase block (cutouts, facts, details, skates guide) in `templates/product.json`, used only for the product picked in its "Product" setting (Ice Version); other products show their own photos.
- **Header (redesigned 13 Oct 2026, owner: "too plain"):** black bar with a soft top light and hairline; logo left, category links centred (desktop), actions right. The active link gets a small dot (the logo's dot), hover shows it faintly. Language as a text select with a globe icon. Cart = "CART" + round count badge (outlined when empty, filled white with items, bumps on change). Soft shadow once scrolled. Phone menu: full-width dark panel with large numbered links (01 Skates…), About and language.
- **Footer (owner request; restyled 14 Oct 2026):** content stays minimal, as on the original site: wordmark, "© year rawdot. All rights reserved.", "Socials" (one link to the owner's Linktree, theme setting `social_links_url`) and "Legal", a small menu that opens upward to the policies. Never repeat header content (categories, About) in the footer, and never list the policies openly; the owner rejected both as redundant and too big. Design only: compact black bar with soft light, a dot grid fading in from the right and one thin ring; Socials and Legal as spaced uppercase links with a small arrow/chevron; the Legal menu is a dark card.
- **Cart:** quantity − / + stepper; changes and removals apply immediately (cart/change.js, then the cart section re-renders from the server), no "Update cart" button when JavaScript runs. Toasts (owner request, 15 Oct 2026; quantity changes too: "Cart updated · <product> · Quantity n"): a small black card at the bottom (bottom-right on desktop, above the fixed buy bar on phones) with the brand dot, the product photo, "Added to cart · View cart" or "Removed from cart · Undo" (undo re-adds the same variant and quantity); one at a time, 5 s with a thin countdown line, paused on hover/focus.
- **Homepage rhythm:** the skates guide's installation section is a full-width dark band (soft spotlight, faint dots), as the original site alternated light and dark; the black installation images sit on it.
- **Page backgrounds (owner request, 13 Oct 2026):** every page except the homepage and policies uses the original site's background (`snippets/backdrop.liquid`): two-size dot grid, slowly drifting soft light, thin floating rings. Policy pages have their own theme (owner: no second nav bar, different background): graph-paper grid (`backdrop` variant `paper`), title on the page, a numbered index of every policy beside the text on desktop (after it on phones, `snippets/policy-index.liquid`), and the text in a white card.
- **Legal (owner direction, 13–14 Oct 2026):** Mexico only (no EU/UK rules, no international shipping or duties; revisit if the US is added). Maximum protection for the seller within Mexican law: all sales final; only the exceptions the law requires (defective, wrong, incomplete or damaged in transit → replacement first; withdrawal right only for sealed, unused products, return shipping paid by the customer). Drafts in Spanish and English are in the owner's Claude Doc "rawdot — Políticas legales"; by owner decision they publish no legal name, address or phone (seller details "provided on request by email"; the owner was told this doesn't meet LFPC art. 76 Bis and that a virtual office and business number would fix it). The owner fills in processing days and the date, then pastes them in Shopify (Settings → Policies in Spanish, the default; English via Translate & Adapt).
- **Experimental effects (trial, 15 Oct 2026, not approved):** two Canvas UI effects (github.com/DavidHDev/canvas-ui, MIT + Commons Clause) bundled with three.js into `assets/fx-canvas.js`; loaded only when the preview URL has `?fx=1` (remembered for the tab; `?fx=0` turns off), never with reduced motion. About panel: the rawdot mark as white dust that scatters around the cursor (ParticleObject). Arm sleeve placeholder: the mark turning in halftone dots (DitheredObject); no longer visible since the sleeve has photos. Rebuild: esbuild IIFE with `--define:import.meta.url='"https://rawdot.shop/"'`. Remove both (assets, theme.js block, CSS block) if the owner rejects them; if approved, drop the `?fx` gate.
- **SEO (15 Oct 2026):** browser-tab title is just "Rawdot" on the homepage and "<page> | Rawdot" elsewhere (owner request, 15 Oct 2026, capital R accepted here; told this is also the Google title). Homepage description, description and visually hidden H1 come from locale keys `seo.*` (written for search per language; Mexican Spanish says "mouse", never "ratón"). JSON-LD: `snippets/site-structured-data.liquid` (Organization with socials + WebSite with search) on every page; `snippets/product-structured-data.liquid` (brand "rawdot", MXN offer, availability, MerchantReturnNotPermitted) for each purchasable homepage product and on product pages; FAQPage from the skates FAQ. Share image `assets/og-image.jpg` (1200×630) on the homepage and wherever no page image exists. Favicons from theme assets (`favicon.svg`, 48/96/192 PNG, apple-touch-icon) unless the theme setting is set. Search, cart and account pages are noindex. Product handle is `ice-version-mouse-skates` (old `https-rawdot-shop` redirects). The owner chose to keep "Rawdot" capitalised in the product SEO title and vendor; don't suggest changing it again.
- **Editor texts are translated (15 Oct 2026):** showcase block texts (tagline, spec and detail values/labels) are typed in English in the theme editor; `sections/showcase.liquid` looks each one up as `content.<handleized text>` in the locale files (handleize the text first, then prepend `content.`) and prints it as typed when no translation exists. New editor texts need a `content.*` entry in `en.default.json` and `es.json`. Shopify's own translation of these settings (Translate & Adapt machine-translated them into "Velocity", "Version Control"…) is ignored: in non-primary languages `snippets/block-text.liquid` reads the English source from the locale key `blocks.<block id>.<field>` (copied into every locale file) and then looks it up as above. When an editor text changes, update its `blocks.*` entry too, or English keeps the old text.
- **Languages:** theme text in en, es, fr, de, it, pt-BR, ja, ko, zh-CN, ar. Only English and Spanish are active in Shopify; Spanish is the default language since 15 Oct 2026 (rawdot.shop = es, /en = en) (owner decision, 14 Oct 2026: selling in Mexico now, maybe the US later; shipping elsewhere is too expensive to compete). The other locale files stay ready; a language is switched on together with its market (Settings → Languages, product content in Translate & Adapt). First visit (owner request, 15 Oct 2026): an inline script in `layout/theme.liquid` opens the store in the device language (navigator.languages, exact then base match) if the store offers it, else the default (Spanish); only on primary-locale URLs, not for crawlers or the theme editor, once per browser (`localStorage rawdot-language`); a language picked in the selector sticks. Prices always show the currency code (`money_with_currency`); with the Mexico-only market that is always MXN, not location detection.
- **Price (owner, 15 Oct 2026):** when a variant has a compare-at price, the buy bar shows it struck through before the price (`snippets/price.liquid`, e.g. "~~$279~~ $199.00 MXN") and a "−29%" tag next to "Disponible".
- **Contact:** the page with handle `contact` (or template suffix `contact`) shows Shopify's contact form under its content (`sections/main-page.liquid`); messages go to the store email.
- **Audit (15 Oct 2026):** four-role audit (bugs, marketing, design, general) fixed in the theme: phone buy bar no longer under the footer, no sideways shift after See more, glasspad facts one column each, product-page parity, JSON-LD images/description/SKU, og:locale es_MX/en_US, noindex on collections, screen-reader cart count, stepper focus, cart lines by key, Escape/outside click closes Legal and the phone menu, Back shows the default category, steady panel height, smaller guide headings, 11px fact labels, install steps as text on phones, add-to-cart errors as a toast.
- **Search engines:** theme settings `google_site_verification` and `bing_site_verification` (Theme settings → Search engines) print the verification meta tags; the owner pastes the codes.
- **Pushing:** a full `theme push` once left the live `templates/index.json` unchanged; after a push that changes it, check the live page, and push it again with `--only templates/index.json` if needed.
